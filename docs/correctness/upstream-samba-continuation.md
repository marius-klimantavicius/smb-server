## Observable boundary

Every new assertion reaches a public SMB command. `P2Tests.Direct` negotiates a connection and establishes a signed authenticated session before dispatch; this is a direct dispatcher fixture, not TCP authentication or external-client interoperability. CREATE obtains all leases, oplocks, durable grants and replay claims. No grant, durable record, replay registry, lock or private manager is seeded. Established extra channels in the direct multichannel tests are fixture state, not an on-wire binding claim. The additional previous-session and notify-lifetime peers perform actual NTLM over direct protocol exchanges; this is still not a TCP interoperability claim. Successful session reauth/binding algorithms are owned separately. Native namespace/notification tests, the three-client CREATE race and deny/share matrix use authenticated signed real TCP with LocalFileStore. Host bytes only corroborate wire effects.

Compound packets carry separately signed components. SMB202 response components are checked with BCL HMAC-SHA256. SMB300 scheduling fixtures use the existing CMAC primitive for signing/verification; their independent oracles are wire fields, literal source/spec statuses and bytes, not a claim of an independently implemented cryptographic stack. Errors with an unresolved all-ones SessionId have no established signing key. Compound message IDs use unused negotiated-window positions, with ordinary signed ECHO progression; no credit ledger is injected. No test queries private resource counters as its conformance oracle. The recording sender and optional send barrier control delivery timing only; assertions inspect SMB responses and notifications.

## Independent requirements and source policies

- [MS-SMB2 QUERY_INFO](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/abb48417-27e5-4a16-82e0-3e5981db97e8), [IOCTL](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/c348a671-7750-49f8-9e61-cc59fa1a5701), and [FSCC FileFsDeviceInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/616b66d5-b335-4e1c-8f87-b4a55e8d3e4a) independently define information/access/buffer fields, handle validation and FILE_DEVICE_DISK=7.
- [MS-FSCC FileAllInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/95f3056a-ebc1-4f5d-b938-3f68a44677a6) embeds the actual per-open granted access mask. Execute-only READ and READ_ATTRIBUTES/READ_CONTROL checks follow the public command access rules.
- Lease READ=1, HANDLE=2, WRITE=4. The literal break-results and mixed lease/oplock source tables provide exact compatibility policies. A more conservative cache grant/revocation can be protocol compliant: these REDs are source compatibility findings, not automatically MUST violations. Parent review must distinguish grant discretion from invalid ACK handling, stale BREAK_IN_PROGRESS, missing notifications or pre-ACK mutation.
- Pending CREATE replay rows use the Samba sane branch, FILE_NOT_AVAILABLE (`0xc0000467`, independently confirmed by [MS-ERREF](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55)). Windows-source counterparts expecting ACCESS_DENIED or SHARING_VIOLATION for the same pending replay are alternative policies, not simultaneously imposed contradictory tests.
- Read directory INVALID_DEVICE_REQUEST versus FILE_IS_A_DIRECTORY, leading-separator validation, and invalid impersonation have host/SHOULD/source-policy distinctions. They remain visible compatibility assertions; a source status difference alone is not called a mandatory defect.
- Optional sparse/allocation/compression/snapshot controls and unsupported information classes are tested for honest rejection, not successful support. Snapshot enumeration permits NOT_SUPPORTED or INVALID_DEVICE_REQUEST, as the source itself does. TWrp requests for an unavailable historical snapshot must not silently access the live namespace. Unsupported CREATE AlSi is ignored as required by [MS-SMB2 3.3.5.9.3](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/3f343618-01b0-4aaf-b8a3-b270f9a6d334), rather than rejected; physical reservation support is not claimed. Basic SET_SECURITY descriptor storage and enforcement already exist. Corrected cases assert success, exact ACE readback, fresh allow/deny admission and surviving old grants. Inheritance and special SID rules are tested separately. The optional atomic CREATE SecD context is unsupported and must reject before acquisition; this is distinct from supported SET_SECURITY. A success acknowledgment without enforcement is never treated as support.
- Existing [capabilities](capabilities.md) still govern host case sensitivity, approximate ChangeTime, process-memory streams/EAs, physical allocation, no directory caching and no persistent/CA recovery. No universal case folding, NTFS creation-time persistence, delayed-write timing, or KDC substitution is assumed.

## Fixture and oracle corrections

The original RED logs and exact source snapshots remain. Corrections are narrowly justified by public packet layout, source applicability or independent specification text:

- FileNamesInformation has a 12-byte name record; CLOSE EOF is at absolute offset112, while104 is allocation. Device information reports FILE_DEVICE_DISK=7.
- Basic DACL SET is supported and enforced. Valid allow/deny/INHERIT_ONLY/owner/generic/namespace rows require successful storage, exact readback and fresh admission decisions. They no longer incorrectly demand NOT_SUPPORTED. Atomic SecD CREATE is a separate unsupported context. The descriptor/CREATE/grant owners' focused fixes are documented in [descriptor repairs](upstream-descriptor-repairs.md), [CREATE authorization](upstream-create-authorization.md) and [grant repairs](upstream-grant-repairs.md).
- Normalized-name class48 rejects NOT_SUPPORTED. Other unsupported file/volume classes retain their specified/profile statuses. A classic ACK without a Breaking obligation rejects INVALID_DEVICE_STATE under [MS-SMB2 3.3.5.22.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/90f21fc9-3094-4d29-842d-55e9aeaf1d05).
- Deny-delete stream fixtures no longer seed a DELETE-capable base open that conflicts before the intended probe. Async CANCEL routing preserves the high AsyncId word instead of overwriting it with TreeId. Wrong-client durable claims are leased when asserting lease-qualified ClientGuid validation.
- Completed CREATE replay is tested before WRITE retires replay eligibility. Lease replay uses the actual upgraded common state7 and source sidegrade requestR. The pinned `test_replay_dhv2_lease_oplock` constructs io2 but sends unchanged io1; its actual lease-upgrade assertion is mapped honestly, with the genuinely altered lease-to-batch request separate.
- [MS-SMB2 client signature verification](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/36172e53-ac81-48fb-b2e3-caa3761b9157) skips STATUS_PENDING. The negotiated peer now permits unsigned async interims while still requiring authenticated terminal signatures. This resolves three notify cleanup fixtures; failed reauthentication still exposes an unsigned terminal LOGON_FAILURE and remains RED.
- Unsupported AlSi **must be ignored** under [MS-SMB2 3.3.5.9.3](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/3f343618-01b0-4aaf-b8a3-b270f9a6d334). The old NOT_SUPPORTED assertion was invalid. The maintained workflow checks successful ordinary durable CREATE, no fabricated allocation/EOF, WRITE, disconnect/reconnect and exact bytes, without claiming physical reservation support.
- A classic lock sequence now checks its prerequisite source level-II grant before demanding a later invalidation. NONE cannot need another cache revocation; the more conservative grant remains an explicit source-policy RED. No cache target was changed to the observed target merely to pass.
- The missing Share namespace, the own tree-key narrowing compile error and the earlier missing RawSmb.Logoff builder are preserved in build logs. Current maintained compilation includes all owners' registrations and succeeds.

The inherited-marker workflow remains failed at source partition0: expected0, actualINHERITED_ACE16. The basic profile records actual inherited origin; [MS-DTYP ACE_HEADER](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/628ebb1d-c509-4ea0-a10f-77ef97ca4586) does not establish a mandatory requirement to erase that origin solely from the parent's zero control combination. Independent descriptor control normalization and MAXIMUM_ALLOWED/readonly filtering now pass. The marker is a source-profile decision, not a reason to undo the focused repairs.
